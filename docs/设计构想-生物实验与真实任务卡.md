## 一、这个项目到底是什么

不是「一个能看太阳系的玩具」，而是**一个在电脑上做太空工程的实验台**。

区别在于：玩具追求好看，实验台追求**可复现**。孩子调参数不是为了画面漂亮，而是为了让某件事发生。

### 已否决的方向（不要回头）

| 被否决 | 原因 |
|---|---|
| 关卡制 | 关卡把「失败」定义成「还没过关」。孩子第一关卡住就不玩了。 |
| 系统派任务清单 | IB 强调 **student-initiated inquiry**（学生发起的探究）。系统给任务 = 老师驱动，探究不成立。 |
| 预设生物形态 | 有形态 = 系统提前替孩子把物理做了，孩子只是在挑预设答案。 |
| 「孩子模式」开关 | 措辞层无条件改造，不做开关分层。 |
| 成功档案以徽章为主 | 徽章是收集动机，会盖过推理动机。失败比成功更该被呈现。 |

## 二、核心概念

### 2.1 「附近」是解锁的钥匙

孩子在调整火箭参数，让它路过某颗星球。**只要算靠近就算数**（不需要降落），此时触发该星球的档案。

### 2.2 档案不是「这里有生物」，而是「这里能不能有生物」

档案内容 = 这颗星球的物理参数（引力、大气密度与成分、公转、自转、潮汐、自转轴倾角、偏心率）
+ **一组判据**，据此推导「什么样的生物能在这里生活」。

每条推演必须标明可信度分级，防止伪科学：

- **硬约束** —— 物理直接决定，如金星 92 atm、水星真空
- **部分约束** —— 取决于生物自身设计，如密度决定是沉还是浮
- **纯想象** —— 物理上不可能，但作为思想实验保留

> 水星一条曾被误判：用户原话「水星尺寸很小、重力很低、潮汐力很大，生物可能个头很大」。
> **校准**：水星自身潮汐力很弱（它太小）。真正大的是**太阳对水星的潮汐加热**
> （3:2 自旋轨道共振 + 高偏心率）。后果不是「个头很大」，而是向阳面 430 °C、
> 背阴面 −180 °C、昼夜温差约 600 °C —— 任何已知化学能都难以稳定循环。
> 所以水星应标为「纯想象」，这反而是一个很好的教学点。

### 2.3 木星/土星的正确物理

- 木星、土星**有**岩石/冰核心（木星约 10–25 地球质量，土星约 9–22），真正的问题是**没有表面**。
- 生物**不会「直接坠落」**：密度随深度上升，物体下沉到所在层密度等于自身密度时停住（浮力 = 重力）。
  - 密度 0.001 g/cm³ 的气囊生物 → 停在约 10 bar / 300 K
  - 密度 1 g/cm³ 的实心生物 → 沉到约 5000 bar / 2000 K
- **两种结果都能用同一条判据算出**，而不是预先写好文字。

### 2.4 行星数据基线

| 星体 | 关键数据 |
|---|---|
| 金星 | 464 °C、96.5% CO₂、硫酸云、92 atm |
| 火星 | −60 °C、0.6 kPa |
| 木星/土星 | 云层 1–5 bar；深层数千 bar、数千 K |
| 水星 | 向阳面 430 °C / 背阴面 −180 °C |
| 天王星 | 轴倾角 98° → 约 42 年极昼 + 42 年极夜 |
| 月球 | 真空、无磁场、昼夜温差约 300 °C |

### 2.5 月球：第一期的唯一目标（2026-11-07 决策）

用户决策：**第一期只在月球上做**。火星、金星先等一等，等「月球上的投放 → 观测 → 调整生物」
这条完整链路跑通再谈后面的事。

月球是最简单的起点，但它一点都不简单——**它是全部太阳系天体里唯一「我们真的知道全部答案」的一个**：

| 判据 | 数值 | 对生物的后果 |
|---|---|---|
| 表面重力 g | 1.62 m/s²（地球 1/6） | 结构压力小 → **允许很大体型**；但没有浮力 → 必须自己承重 |
| 大气 | **真空**（≈0） | 无法呼吸；**无法靠浮力** → 必须自持密封结构；体液在 6.11 mPa 三相点以下立即沸腾 |
| 表面温度 | −170 °C（夜）~ +120 °C（昼） | 无大气调温 → **昼夜温差约 290 °C**，必须隔热/辐射散热 |
| 昼夜周期 | 约 29.5 地球日 | 白天约 1361 W/m² 直射，夜间辐射冷却 |
| 磁场 | **无** | 无磁屏蔽 → 银河宇宙射线直击表面，辐射损伤累积 |
| 表面 | 月壤（regolith） | 细颗粒含玻璃质，粉尘易扬起，无风但有静电悬浮 |
| 微陨石 | 持续轰击 | 地球被大气烧掉了大部分，月球没有防护 |
| 特殊地点 | **永久阴影坑（PSR）** | 月球南极有永不见光的坑，理论温度约 25 K（−248 °C），**可能存在水冰** |

两个教学价值极高的点：

1. **低重力 = 大体型可行**。用户最早的想法「火星引力小 → 物体相对比例大于人」在月球更成立
   （1/6 vs 火星 0.38）。L² 结构强度 scaling 遇上低重力，允许的体型上限被显著推高。
2. **永久阴影坑**。这是太阳系里最有 astrobiology 价值的地点之一：
   永夜 + 可能的水冰 + 极端稳定 → 教科书级「找地外生命的第一个目标」。
   而且它是**月球内部的第二个位置**，天然引出「栖息层」概念（表面 vs 坑内）。

> 第一期的月球判据要点：不是「月球没生物」，而是**能逐条说出为什么难**——
> 真空（不能呼吸）、无浮力（必须承重）、温差 290 °C（必须隔热）、无磁屏蔽（辐射）、
> 微陨石（撞击）。每一条都对应一次可复现的尸检。

## 三、实验日志（纯数据，不是进度条）

### 3.1 定位

**它是本项目里唯一的「证据链」**，别的地方可以是玩具，唯独这张表是「我做过什么」的证据。

只存：编号、时间、**全部参数**、结果、结论。
**不放**：徽章、评分、"第几次成功"、推荐参数、最佳方向。评价留给使用者自己写的结论。

徽章与档案另放「档案墙」界面，与日志分开。

### 3.2 交互（用户明确要求）

- **抽屉形态，但要明显、稍宽**，不能是极窄小边 —— 作用是持续提醒「我们在做实验」。
- 建议实现：底部常驻一条约 48px 高的「实验本条」（显示 `23 次实验 · 最近 #23 近月点 8,700 km`），
  点击从右侧滑出宽抽屉，宽 `max(420px, 42vw)`，平板横屏接近半屏。
- 位置放**左下角**，避开右下角 🚀📖🔇 工具条与底部中央日期组。
- **必须像 Excel 一样点表头排序**（升序/降序切换）。第一版就做。

### 3.3 为什么排序是核心功能而非便利功能

- 按时间排 =「我试了 23 次」，没有信息。
- 按推力排 = 立刻看到「0.1G 全掉下来，2.6G 开始入轨」—— **一条规律从数据里长出来了，而且是他自己排出来的。**
- 这就是 IB **Criterion C（处理与评价）** 的核心动作，且最容易被跳过。
- 副作用：**排序会暴露空白**。按推力排后 2.8G 那一列是空的 → 空格会自己勾人，不需要系统派任务。

正序倒序都允许，**系统不评判**。

## 四、IB 框架对齐

### 4.1 PYP 探究六步 → 界面映射

| 步骤 | 英文 | 落到哪个界面 |
|---|---|---|
| 导入激发 | Tuning In | 一轨意外的轨迹（不是「任务」） |
| 搜集信息 | Finding Out | 这颗星球的数据 |
| 整理归纳 | Sorting Out | 哪条判据先崩 |
| 深入探究 | Going Further | 换一个变量再试 |
| 建立联系 | Making Connections | 和真实任务对照 |
| 采取行动 | Taking Action | 下一个问题是什么 |

### 4.2 MYP 三个评判标准 → 已有界面

| 标准 | 对应 |
|---|---|
| B 探究与设计 | 研究问题、**假设**、变量（自变量/因变量/控制变量）、方法步骤 |
| C 处理与评价 | 数据表、结论、**误差来源**、方法局限、改进方案 |
| D 反思 | 这改变了你什么想法、科学的影响、伦理 |

C 里的「误差与局限」正好对应尸检报告里的置信度：
只说「464 °C」是事实；说「464 °C ± 少量，未计入气压对沸点的影响」才是科学。
这会教孩子一件事：**任何结论都附带条件**。

### 4.3 NOS（科学的本质）

1. 科学知识是**暂定的、可修正的** → 结论要带误差
2. 科学是**人类的努力**，受社会/文化/政治影响 → Phobos-Grunt 的失败有预算原因
3. 科学**依赖证据，也依赖创造力和想象力** → 假说需要想象，验证需要证据

### 4.4 探究问题分三类

- **事实性**（火星气压多少）→ 查得到，不算探究
- **概念性**（为什么行星大小限制生物体型上限）→ 真探究
- **辩论性**（该不该把生物送上火星）→ 伦理

产品可做的很轻：提问时回一句「这是事实性问题，可以直接查；换个问法试试？」——
**帮他把问题从「查得到」升级到「想不通」**。

### 4.5 预测：探究与试错的分界线

- 只调参数看结果 = **试**
- 先说「我猜会怎样」再跑 = **探究**

因为预测把结果变成**可被推翻**的。

提问不要写「请写下你的假设」（太学术），写：

> **你猜会发生什么？**
> **你为什么会这么猜？**

第二句才是关键，它把**直觉变成假设**。直觉是**待检验的资产**，不是要纠正的错误
（爱因斯坦坚持光速不变，在当时就是反直觉的）。
它顺便教一件事：科学不是「猜对了很厉害」，而是「你的猜测有没有理由」。

> **待定**：预测是投放前必须填，还是事后补填？倾向投放前必须填（事后补填变成编故事），
> 但可能挡住「就是想快点试试」的孩子 → 也许给一个「跳过预测」的小出口。

## 五、生物 = 参数组合，没有预设形态

### 5.1 维度清单（用户明确要求：自由组合，怎么组合都可以）

| 维度 | 取值范围 | 它决定什么 | 被哪条星球判据否决 |
|---|---|---|---|
| 体长 L | 0.1 m – 30 m | 质量与结构强度（L² 缩放） | 重力过小 → 弹飞；重力过大 → 骨架压垮 |
| **密度 ρ** | 0.01 – 5000 kg/m³ | 质量、是否浮得起来、沉到哪一层 | 太重 → 压碎；太轻 → 升到不适合的高度 |
| 外壳抗压 | 0.1 – 200 atm | 能扛住多高的外界压力 | 金星 92 atm｜水星真空｜木星 1–5 bar |
| 溶剂 | 水 / 氨 / 甲烷 / 烃 | 沸点与凝固点 | 表面温度 vs 该溶剂沸点（−60 °C 对 100 °C） |
| 能量来源 | 光合 / 化能 / 发酵 | 能量从哪来 | 有无液态水｜有无化学能梯度｜有无光 |
| 移动方式 | 行走 / 漂浮 / 滑行 / 飞行 | 加速度耐受、活动半径 | 重力强弱｜流体密度｜是否有可踩踏表面 |
| 群体规模 | 1 / 10² / 10⁶ | 生态系统能否建立 | 太轻站不住 → 群体质量累积可压住地面 |

**第一版只做「体长 L」和「密度 ρ」两个连续滑杆**（不是档位！），因为用户举的关键例子
「体积很大但密度很低」「体积很大密度也很大」只有连续轴才试得出来。

**群体规模**第一版恒为 1，但数据模型保留 `population` 字段。
它是**从失败里长出来的变量**：当孩子在火星上发现单只太轻站不住，
群体（个体质量累积）是他自己会想到的解法。

### 5.2 核心物理：形态自由度来自「内外压差」，不是「材料强度」

用户原话：「因为气压大，气压跟浮力似的，它上下会有压差，那它可能会非常非常薄，甚至只有一个原子的厚度。」

**方向对，但卡点需要校准**：

- 生物要扛两股力：自身重量（向下）、外界压差（从四面八方挤压）。压差随深度线性增长（dp/dz = ρg），
  所以高压环境中的生物进化方向是**扁平**（减少高度方向尺寸）。
- **「只有一个原子厚度」物理上不成立**：卡点不是厚度而是**剪应力**——
  单层原子层抗拉很强但抗剪切极差，强度上限远低于 92 atm 下的结构需求。
- **真正的解法是换个思路：不靠强度，靠浮力。**
  如果生物是气囊，内部压力可做到**与外界相等**（中性浮力），
  那么它**不需要任何结构强度** —— 形状由内外压差决定，材料薄到任何程度都可以。

> **想要极薄的身体？不要去加强材料，去改变浮力。**
> 这就是密度滑杆在教的东西。

由此得到两条路线：

| 密度关系 | 路线 | 形态自由度 |
|---|---|---|
| ρ < 环境 | **浮力路线** | 内外压差 ≈ 0，不必靠材料承力 → 形态可以极端（气囊、扁平、丝状） |
| ρ ≈ 环境 | 中性浮力 | 停在等密度层（木星约 10 bar/300 K；金星硫酸云 50–60 km） |
| ρ > 环境 | **强度路线** | 必须靠结构承重 → 形态被强度上限压缩（只能小、壳必须厚） |

**「巨大且高密度」必然失败**：L² 结构强度 scaling 跟不上 L³ 重量增长。

### 5.3 同一组参数在不同星球上的结果（推演示例）

| 密度关系 | 月球 · 真空 | 火星 · 0.6 kPa | 金星 · 92 atm | 木星 · 云层 1–5 bar |
|---|---|---|---|---|
| ρ 小于环境<br>浮力路线 | 无浮力可用<br>只能极轻或自撑 | 浮力太弱<br>只飘得起极轻物 | 硫酸云中飘<br>云层 50–60 km | **巨型气囊**<br>停在 10 bar 层 |
| ρ ≈ 环境<br>中性浮力 | 不适用<br>真空中没有环境密度 | 悬在稀薄大气<br>随风吹走 | 云层中性<br>稳定悬浮 | 停在某一层<br>深度由密度定 |
| ρ 大于环境<br>强度路线 | 厚壳球体<br>只能靠辐射散热 | 皮肤加压舱<br>最舒服的一颗 | 极扁或极硬壳<br>要抗 92 bar | 沉到 5000 bar<br>2000 K，必死 |

注意：**同一个「密度 0.001 的轻生物」，在月球是灾难，在金星是天赐** ——
因为金星有大气层提供浮力，月球没有。

### 5.4 判据必须分层（不只是加滑杆）

用户提醒：「先放出两个维度，可能只能应付月球和火星，面对金星会有大麻烦。」

**判断：问题不在维度数量不够，而在判据本身需要分层。** 金星的麻烦来自「金星有大气层 + 有硫酸云 + 有浅海」
→ 存在「住在液体/气体里」这个选项 → 必须回答「它会不会沉下去」。

```
第一层：能不能在那个位置「存在」？
  ├─ 真空（月球）→ 必须自持结构，无浮力可用
  ├─ 稀薄大气（火星）→ 浮力微弱，需质量压住地面
  └─ 浓密大气（金星/木星）→ 可选：待在气体层里
第二层：待在哪一层？
  ├─ 表面 ├─ 云层悬浮 └─ 内部等密度层
第三层：那一层的温度、压力、光照、化学梯度
```

**栖息层**（第 8 个维度）= 离散策略选择（站在表面 / 泡在液体里 / 飘在云层 / 沉在内部等密度层），
不是滑杆。第一版先只做「系统在多层里自动找最优」，第二版再让孩子显式选。

### 5.5 形态必须程序化生成，不能预先画图

用户明确要求：「它的形态肯定不是人的样子，可能是各种形态……都需要试出来。」

- 形态写成**极坐标半径函数 r(θ)**，按参数施加形变：
  - 压差梯度大 → 沿压力轴压扁、垂直轴拉长
  - 密度接近环境 → 向气体方向膨胀，r 整体放大且起伏加强
  - 密度远大于环境 → r 收缩、壳壁加厚、整体变紧凑团块
- 拖动密度滑杆时形态**连续变形**（不是切换图片）→ 因果关系直接可见，不需要读文字。
- 同一组参数应给出**多个可行解**（球/扁/丝状），呼应「没有唯一解」。
- **界面纪律：系统绝不显示「正确形态」**，不预设、不剧透。形态必须在模拟中自己长出来或崩掉。

## 六、尸检报告

### 6.1 唯一主因

**主因只有一条**（第一次不可逆损伤），其余标为「后续后果（已无生态意义）」。
这样报告只教一个改法，而不是五条并列死因。

### 6.2 时间顺序由物理传输速率算出，不能编剧本

| 机制 | 时间尺度 | 为什么 |
|---|---|---|
| 压力崩溃 | 毫秒级 | 压力波以声速传播，1 m 物体约 1 ms |
| 真空沸腾 | 瞬间 | 体液在低于三相点时表面立刻沸腾 |
| 热变性（烧死） | 秒级 | 取决于导热系数与体积/表面积比 |
| 冻僵 | 十秒到分钟 | 取决于热容，体积越大越慢 |

例（金星地表投放，10 倍慢放回放）：

```
0.12 s  蛋白质变性   464 °C · 不可逆          ← 主因
0.31 s  外壳压溃     92 atm · 已无意义        ← 后续后果
1.20 s  完全碳化     代谢全部停止             ← 后续后果
```

孩子会自己发现：**压溃比烧死快得多**（一个声速传播，一个靠热传导）。

### 6.3 必须可追溯

- 每种死法对应**唯一一条判据**。不能给「运气不好」这种答案。
  - 蒸发 = 气压低于三相点
  - 烧毁 = 温度超过蛋白质变性阈值
  - 压碎 = 外部压力超过外壳抗压
  - 冻僵 = 低于溶剂凝固点
  - 窒息 = 缺少电子受体
- 死亡过程快、可见（0.5 秒内形态崩解），然后弹报告，带具体数字：
  `表面温度 464 °C｜外壳抗压上限 3 atm｜实际外部压力 92 atm`
- **第一次尝试必然失败应该是设计目标之一**：第一次就成功说明这个实验没有信息量。

## 七、失败档案

### 7.1 与自己的实验记录并置

不做独立栏目。上半屏是真实历史（如 Mars 3 的 14 秒），下半屏是他自己的第 8 次「0.12 秒死亡」。
**并置**比说教更有说服力：他不再是「我失败了」，而是「我正走在同一条路上」。

### 7.2 必须校准的一句话

> **发现是偶然的，工程是设计的。**

- 讲**发现**时强调偶然：青霉素（Fleming 观察到污染霉菌周围出现抑菌圈）、
  宇宙微波背景辐射（彭齐亚斯与威尔逊本来在清理天线噪声）。
- 讲**工程**时强调失败的数量：Mars 3 软着陆后仅工作 14 秒、
  Phobos-Grunt 连地球轨道都没能离开、Mars Observer 在进入火星轨道前失联。

若只强调「成功全靠运气」，孩子会得出「那我等运气就行」的结论 —— 这是科学教育最怕的副作用。

### 7.3 严谨与好玩的边界

> **一次失败的实验，必须产出一条他之前不知道的信息。否则它就不是实验，只是惩罚。**

不奖励：不给星星、不给连续通关记录、不给排行榜。只给数据、给结论、给下一个可试的方向。

## 八、入口设计：怎么让孩子自己发起探究

### 8.1 给缺口，不给任务

- **困境**是负面的（我要摆脱它），解决了就没动力了。
- **悬念**是正面的（我想知道），它会一直勾着人。

IB 里这叫 **provocation**（激发情境）：不告诉学生研究什么，而是**摆一个让他不舒服、想弄明白的东西**。

### 8.2 核心手法：把「任务」变成「工具」

| 任务式 | 工具式 |
|---|---|
| 「你去火星。」→ 孩子被派活 | 「这是你的相机，你能拍多远？」→ 孩子使用工具 |

一旦变成工具，「去火星」就是**他自己想达成的目的**，不再是一道题。

### 8.3 五种缺口（从弱到强）

1. **看不清** —— 打开就是一颗 64 像素的模糊地球，本能地想拉近，拉到最远还是糊
2. **够不着** —— 想拍火星，相机分辨率不够，火星在 2 亿公里外
3. **我以为…其实**（最强）—— 孩子的直觉来自电影：火星红色沙漠、能走路、可能有点冷。
   实际显示 −60 °C、0.6 kPa。**用孩子自己的预测制造悬念**
4. **意外** —— 轨道跑到奇怪的地方，偏差 0.7 AU
5. **真实困境** —— 阿波罗 13 号氧气罐爆炸（历史给的，不是系统给的）

### 8.4 需求精确化本身就是探究

| 孩子的模糊愿望 | 精确化之后 | 需要的任务 |
|---|---|---|
| 看地球 | 看**全貌**还是看**细节**？ | 全貌要高轨/够远；细节要低轨或飞机 |
| 看行星 | 卫星在轨道上**拍不到**别的行星 | 必须用探测器：环绕 / 飞掠 / 着陆 |

> **卫星拍不了其他行星** —— 它和地球一起绕太阳转，永远追不上。
> 这个「不行」本身就是一课。

### 8.5 low floor, high ceiling

孩子平时是「消费者」，第一次打开就自己提问不现实。降低难度的办法不是降低要求，
而是**先给台阶，再撤台阶**：

- 第一次打开只给他一个**能拉近的镜头**。他能拉，拉到头卡住。系统一句话都不说。
- 绝大多数孩子会自己再拉一次、再换方向拉 —— **这就是他自己发起的探究**，只是看起来像「玩」。
- 第二三次，台阶慢慢撤掉，镜头不再自动对准行星，他得自己算。

### 8.6 能力边界，而非关卡

不做关卡制。约束只来自物理与火箭技术上限：

> 「这需要猎鹰重型级别」—— 这句话只是**信息**，不是「你不能进下一关」。

解锁不是系统派的，是**他自己调参撞出来的**。顺序取自真实航天史：

| 级别 | 年份 | 任务 | 新解锁的参数 |
|---|---|---|---|
| 1 | 1957 | 地球环绕 | 推力、点火时长 |
| 2 | 1969 | 月球 | + 方位角、发射日期（必须匹配月相） |
| 3 | 1962 | 内行星 | + 深空机动 Δv（近心点对 Δv 极敏感） |
| 4 | 1977 | 外行星 | + 借力窗口 |

**每加一级只加一个新手需要理解的参数。**

## 九、真实任务卡与自由实验的关系

**任务卡是例题，自由实验是习题。**

- 任务卡展示「别人是怎么做的」，让孩子看懂一条真实任务链长什么样（伽利略、卡西尼、帕克、MESSENGER、旅行者 1/2 号、阿波罗 11 号共 7 个）。
- 自由实验是「你自己从零做一次」。
- 以后想「锁起来」，锁的应该是**答案**（不显示近心点高度，只显示「已接近」），**入口不要锁**。
- 现在这些任务卡是**保留的演示**，先不锁。

## 十、待办与未决问题

### 10.1 未决

- 预测是投放前必须填，还是事后补填？是否给「跳过预测」出口？
- 栖息层要不要显式让使用者选，还是系统自动找最优？
- 第一版形态用纯几何 blob，还是必须一眼看出像生物？
- 实验日志抽屉的最终形态（宽度、位置、展开方式）待定。

### 10.2 分期建议（已按 2026-11-07 决策收敛：只做月球）

**第一期（唯一目标：月球）**
1. 实验日志抽屉（明显、稍宽）+ 点表头 Excel 式排序
2. 投放界面：**体长 L + 密度 ρ 两个连续滑杆**
3. 月球判据（见 2.5）：真空、无浮力、温差 290 °C、无磁屏蔽、微陨石、PSR
4. 预测输入（投放前）
5. 形态程序化生成（极坐标 r(θ)），系统不显示正确形态
6. 尸检报告：唯一主因 + 物理传输速率时间戳
7. 观测三级阶梯（见 10.3）

**第二期（月球链路跑通后再谈）**
- 火星、金星完整判据（含金星大气 vs 金星地表的分层）
- 栖息层显式选择 + 群体规模滑杆
- 木星/水星/气态巨星判据
- 失败档案并置 + 档案墙

**长期维护要求**：这个项目要长期迭代维护，任何一轮改动都要保证
① 实验日志可累积（不丢历史）② 判据表可扩展（加星球不改旧逻辑）③ 物理常数集中可查。

### 10.3 观察方式：用户提出的关键疑问

> 「我肯定是要先发射火箭，进行绕月飞行，做完这个才可以进行这个投放、观察。
> 或者没有——如果孩子没有想到说我应该派一个飞行器绕月一直观测，
> 他可能想的是：我先发射一个火箭过去投放，然后过一段时间再发射一个火箭过去再观察。
> 之后可能可以引入：我干脆发一个火箭一直在那里，卫星一直绕月飞行进行观察。」

**这段洞察很重要，它本身就是一个可以做成功能的三级递进：**

| 方案 | 观测方式 | 代价 | 真实对应 |
|---|---|---|---|
| A | 投放时顺带看一眼（随落器回传） | 最低，但只有一瞬间 | 阿波罗 11 号：采样返回 + 就地实验 |
| B | 过一段时间再发射一个火箭去看 | 两次发射，两次窗口 | 阿波罗 12/14/15 号：每次带新的 ALSEP 月面仪器包 |
| C | 常驻轨道器一直绕月观测 | 一次发射，但复杂、需长期维持 | 月球轨道器长期观测 + 阿波罗 11 号角反射器被地面激光测距至今使用 |

**设计含义**：

- 这是**同一个悬念的三种解法**，正好是 IB「建立联系 → 深入探究」的天然载体：
  孩子会问「我投了之后怎么知道它还活着？」→ 自己发现需要「持续的观测者」。
- **不应由系统提示「你应该派个环绕器」**，而应由「投放后没有回传」这个事实引发：
  投完 → 数据只回传投放瞬间的画面 → 之后发生什么？**空白本身就是悬念**。
- 真实依据：阿波罗 11 号留下的**角反射器**至今仍在被地面激光测距，
  月球轨道器拍到过所有阿波罗着陆点 —— 这都是「持续观测」的科学价值实例。

### 10.4 尚未实现的技术前提（与本构想相关）

- 「环绕」预设目前是**高偏心转移轨道型椭圆**，不是 ISS 式近圆轨道。
  若要支持「常驻轨道器持续观测」，需要补上**圆化变轨第二次点火**。
  （这个轨道每次过近地点都会掉进大气层烧掉，撑不到「一直观测」。）
- 「去火星」的**真实窗口期**尚未用真实相位角计算，目前用理想化对齐替代。

## 十一、Git 与发布流程（长期维护用）

### 11.1 目录职责

- `d:\Python Progrem\巡星记` = **Git 主仓库**，物理修复、代码演进、设计文档都在这里。

### 11.2 提交约定

**不要自动 commit / push。** 每轮改动完成后 → 汇报改了什么 → **等用户明确说「commit+push」才执行**。
确认后顺序：① 在主仓库 `git add` + `git commit`（中文提交信息，写清改了什么和为什么）→ ② push → ③ `Copy-Item` 同步 index.html 到共享包镜像。

### 11.3 ⚠️ 本机网络：github.com:443 被阻断，改走 SSH

实测（2026-11-07）：

| 项 | 结果 |
|---|---|
| DNS 解析 github.com | ✅ 正常（20.205.243.166） |
| TCP 443 (github.com) | ❌ **不通**（连接被重置 / 21 秒超时） |
| TCP 80 (github.com) | ✅ 通 |
| TCP 22 (github.com) | ✅ 通 |
| TCP 443 (api.github.com / ssh.github.com) | ✅ 通 |

**结论**：只有 `github.com:443` 被拦，其他域名和端口都正常。所以 `git push` 走 HTTPS 会失败。

**已配置的解法（SSH）**：

- 密钥：`C:\Users\60465\.ssh\id_ed25519_gh`（ed25519，空 passphrase）
- 已注册为**仓库 deploy key**（read/write，id=169007806）
- known_hosts：`C:\Users\60465\.ssh\known_hosts_gh`
- ⚠️ `.ssh\config` **无写权限**，所以不能用 `Host github.com` 配置块，必须用 `-c core.sshCommand=...` 显式传参。
  ⚠️ 路径必须用**正斜杠**，反斜杠会被 git 吃掉（`-i C:/Users/...`）。

**推送命令**（PowerShell）：

```powershell
$env:Path = "C:\Program Files\Git\cmd;" + $env:Path
$sshCmd = 'C:/Windows/System32/OpenSSH/ssh.exe -i C:/Users/60465/.ssh/id_ed25519_gh -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o UserKnownHostsFile=C:/Users/60465/.ssh/known_hosts_gh -o BatchMode=yes -o ConnectTimeout=30'
git -C "d:\Python Progrem\巡星记" -c core.sshCommand="$sshCmd" push git@github.com:TennisCoachLi/solar-odyssey.git main:main
git -C "d:\Python Progrem\巡星记" update-ref refs/remotes/origin/main (git -C "d:\Python Progrem\巡星记" rev-parse HEAD)
```

**注意**：`git fetch origin main` 走 HTTPS 会失败，要 push 时把 `origin` 换成 SSH 地址。
推送后 `git status` 若仍显示 `ahead 1`，用 `update-ref` 手动刷新远程跟踪引用。

### 11.4 其他环境事实

- git 装在 `C:\Program Files\Git\cmd`（不在默认 PATH），调用前需 `$env:Path = "C:\Program Files\Git\cmd;" + $env:Path`

- 该 token **没有 `admin:public_key` scope**，所以 `POST /user/keys` 返回 404；改用仓库 deploy key 成功
